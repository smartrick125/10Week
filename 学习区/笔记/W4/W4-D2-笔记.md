## 1. 一张 RT 占多少字节（15 分钟）

**前提**：只算单采样、没有 mipmap 的 2D 纹理，按未压缩的逻辑大小算。

【推断·算式】一张 RT 的字节数 = 宽 × 高 × 每像素字节数。这是逻辑大小，不是显卡实际分配的大小：显卡可能为对齐多分配，也可能压缩（W3-D3 第 4 节、W3-D2 第 9 节讲过压缩和缓存不在这个模型里）。

【原文】[Unity 6.3 · GraphicsFormat.R8G8B8A8_UNorm](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Experimental.Rendering.GraphicsFormat.R8G8B8A8_UNorm.html)「A four-component, 32-bit unsigned normalized format」（译：一种四分量、32 位的无符号归一化格式）。32 bit = 4 B，所以每像素 4 B（和 W3-D2 第 9 节用的一样）。

【原文】相机颜色 `_CameraTargetAttachment` 实测是 B10G11R11_UFloatPack32（第 2 节）：[GraphicsFormat.B10G11R11_UFloatPack32](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Experimental.Rendering.GraphicsFormat.B10G11R11_UFloatPack32.html)「A three-component, 32-bit packed unsigned floating-point format」（译：一种三分量、32 位打包的无符号浮点格式）。32 bit = 4 B，所以也是每像素 4 B。原因是工程开着 HDR：URP Asset 的 HDR Precision「Default value: 32 bit.」（译：默认值：32 位。）【原文·代码】`PC_RPAsset.asset:26-27` 开 HDR、精度 32 位，URP 17.3 `UniversalRenderPipelineCore.cs:1561-1569` 在这种情况下给相机颜色选 B10G11R11（F54 / V57）。

## 实验记录（10-22，用户要求记进笔记，F53 / V56）：SRP Batcher 让 Frame Debugger 事件数变少

**前提**：W3 用的场景，4 个不透明物体（球、蓝方块、红 cube、绿 cube）加背景；`PC_RPAsset` 开着 SRP Batcher（`PC_RPAsset.asset:72` `m_UseSRPBatcher: 1`）。不属于今天的验收列。

1. **看到的**【观察】：Frame Debugger 里 `DrawOpaqueObjects` 下依次是 `RenderLoop.DrawSRPBatcher`（SRP Batch：球 + 蓝方块）→ `RenderLoop.Draw`（Cube (2)、Cube (1) 各一个 Draw Mesh）→ `RenderLoop.DrawSRPBatcher`（SRP Batch：背景），右边计数 4。
2. **实验**【观察】：把蓝方块的 shader 换成书里的自定义 shader，它离开 SRP Batch，挪到 `RenderLoop.Draw` 下单独画（变成 3 个 Draw Mesh），第一个 SRP Batch 只剩球；计数 4 → 5。实验后已改回原 shader。
3. **SRP Batcher 是什么**：
   - 【原文】[Unity 6.3 · SRP Batcher](https://docs.unity3d.com/6000.3/Documentation/Manual/SRPBatcher.html)「The SRP Batcher reduces the CPU time Unity requires to prepare and dispatch draw calls for materials that use the same shader variant.」（译：对于使用同一个 shader 变体的材质，SRP Batcher 减少 Unity 准备和派发 draw call 所需的 CPU 时间。）
   - 它不减少 draw call 个数：【原文】同页「The traditional way to optimize draw calls is to reduce the number of them. Instead, the SRP Batcher reduces render-state changes between draw calls.」（译：传统的优化 draw call 的办法是减少它们的数量。SRP Batcher 不这样做，它减少的是 draw call 之间的渲染状态变化。）
   - 【原文】同段「Each sequence of commands is called an SRP batch.」（译：每一串这样的命令叫作一个 SRP batch。）Frame Debugger 里的「SRP Batch」就是它。
   - 它和 Stats 的 Batches 不是一回事：【原文】[Rendering Statistics window](https://docs.unity3d.com/6000.3/Documentation/Manual/RenderingStatistics.html) Batches「This number includes static, dynamic, and instance batches.」（译：这个数包括静态、动态和实例化批次。）没列 SRP batch。
4. **为什么蓝方块会离开**：
   - 【原文】[Unity 6.3 · SRP Batcher materials](https://docs.unity3d.com/6000.3/Documentation/Manual/SRPBatcher-Materials.html) 兼容条件有两条：「The shader must declare all built-in engine properties in a single constant buffer named UnityPerDraw.」（译：shader 必须把所有内置引擎属性声明在一个名为 UnityPerDraw 的常量缓冲里。）「The shader must declare all material properties in a single constant buffer named UnityPerMaterial.」（译：shader 必须把所有材质属性声明在一个名为 UnityPerMaterial 的常量缓冲里。）
   - 【原文】同页「All lit and unlit shaders in the the Universal Render Pipeline (URP) … fit this requirement」（译：URP 里所有 lit 和 unlit shader 都满足这个要求），所以用 URP Lit 的球和原来的蓝方块能进 SRP Batch。
   - 自定义 shader 兼不兼容，看一眼就知道：【原文】同页「You can check the compatibility status of a shader in the Inspector panel.」（译：可以在 Inspector 面板里查看一个 shader 的兼容状态。）选中书里那个 shader 文件，在 Inspector 里看一眼。
5. **对账时注意**【推断】：Frame Debugger 里一个 SRP Batch 算 1 个事件，事件数会受 SRP Batcher 影响；Profiler 的 Draw Calls 手册没说怎么数 SRP batch 里的物体，按「每个物体仍有自己的 draw」理解（W4-D1 实测 Batches 和 Draw Calls 都是 18，和这个一致）。两边对不上时，先看有没有 SRP Batch。
