## 2. 三个词：draw call、batch、SetPass（15 分钟）

**前提**：以下定义全部来自 Unity 6.3 手册，是 Unity 工具里这几个数的含义，不是图形 API 的通用定义。draw call 的定义来自 Profiler 的 Rendering 模块；Batches、SetPass 来自 Game 视图的 Statistics 窗口（Statistics 窗口里没有 Draw Calls 这一行）。

1. **draw call**：【原文】[Unity 6.3 · Rendering Profiler module](https://docs.unity3d.com/6000.3/Documentation/Manual/ProfilerRendering.html) Draw Calls「The total number of draw calls Unity issued during a frame. Unity issues draw calls when it renders GameObjects to the screen.」（译：一帧里 Unity 发出的 draw call 总数。Unity 把游戏对象渲染到屏幕上时会发出 draw call。）同一格接着说「This number includes non batched draw calls and dynamic and static batched draw calls.」（译：这个数包括没合批的 draw call，以及动态合批和静态合批的 draw call。）
   - 为什么贵：【原文】[Unity 6.3 · Introduction to optimizing draw calls](https://docs.unity3d.com/6000.3/Documentation/Manual/optimizing-draw-calls.html)：一次 draw call 分两步，「Update the render state.」（译：更新渲染状态。）和「Submit a draw call.」（译：提交一次 draw call。）；第一步「This is the most CPU-intensive step.」（译：这是最耗 CPU 的一步。）
2. **批次（batch）**：【原文】[Unity 6.3 · Rendering Statistics window](https://docs.unity3d.com/6000.3/Documentation/Manual/RenderingStatistics.html) Batches「The total number of draw call batches Unity processes during a frame.」（译：一帧里 Unity 处理的 draw call 批次总数。）同页 Saved by batching「The number of draw calls Unity combined into batches.」（译：Unity 合并进批次的 draw call 数量。），并说「Batches group draw calls with the same render state」（译：批次把渲染状态相同的 draw call 分到一组。）。
3. **SetPass**：【原文】同页 SetPass「The number of times Unity switches which shader pass it uses to render GameObjects during a frame.」（译：一帧里 Unity 切换「用哪个 shader pass 渲染游戏对象」的次数。）

**检查题前提**：只用上面三条原文，不用别的资料。

用自己的话各写一句：draw call、batch、SetPass 分别数的是什么？哪一个和「换 shader pass」直接有关？
__draw call是一次绘制的调用 draw calls是一帧里Unity发送的draw call总数 <span style="color:red">一个 batch 装的是这一帧里渲染状态相同的 draw call（曾错写成「batch是将使用相同渲染状态的网格合并在一起绘制」「渲染状态相同的 pass 一批 pass」：batch 装的是 draw call，不是网格或 pass）</span> batches是在数这一帧中有多少个batch <span style="color:red">一次SetPass是一次切换shaderPass（曾错写成「一次SetPass是一次切换渲染状态」：渲染状态包含 shader pass，反过来不成立）</span> SetPass calls是数这一帧中有几次SetPass，SetPass和换shader pass直接有关__


**答疑记录（10-21，用户要求记进笔记，F49 / V51）：SetPass 里的 pass 和 RenderGraph pass 不是同一个东西**

1. 【原文】同页 SetPass 一格后两句：「A shader might contain several shader passes and each pass renders GameObjects differently. Each pass requires Unity to bind a new shader, which might introduce CPU overhead.」（译：一个 shader 可能包含几个 shader pass，每个 pass 用不同方式渲染游戏对象。每个 pass 都要 Unity 绑定一个新的 shader，这可能带来 CPU 开销。）这里的 pass 是着色器通道（shader pass）。【原文】[Unity 6.3 · Pass block in ShaderLab reference](https://docs.unity3d.com/6000.3/Documentation/Manual/SL-Pass.html)「To define a Pass in ShaderLab, use a Pass block.」（译：在 ShaderLab 里定义一个 Pass，要用 Pass 块。）也就是 `.shader` 文件里的 `Pass { }` 块。
2. 【原文·代码】本工程 `GaussianBlur.shader` 有两个 shader pass：第 83 行起的 `GAUSSIAN_BLUR_VERTICAL`（片元函数 `FragVertical`，:90）和第 95 行起的 `GAUSSIAN_BLUR_HORIZONTAL`（`FragHorizontal`，:102）。C# 用编号选：`GaussianBlur_RenderPass.cs:80` 传 `material, 0`，`:83` 传 `material, 1`。
3. 不是一一对应：
   - 【原文·代码】Downsample（`:76`）、Upsample（`:87`）没传材质，不用 `GaussianBlur.shader`。用哪个 shader 看第 3 节你记下的 `downSample`（SRP Core 17.3 `RenderGraphUtilsBlit.cs:370` 起先判断能不能走 copy，条件之一是源和目标宽高相同，`:118`）：
     - `downSample = 2`：两步的源和目标尺寸不同，走 `AddUnsafePass` + `Blitter.BlitTexture`，材质是 URP 传入的 `CoreBlit.shader`（`UniversalRenderPipeline.cs:244`）。
     - `downSample = 1`：尺寸相同，走 `AddCopyPass`，材质是 `CoreCopy.shader`（`Blitter.cs:166`、`:404`）。
     - 两条路都用一个 shader pass 画一次。
   - 【观察】Frame Debugger 里 `DrawOpaqueObjects` 这一个 RenderGraph pass 下有 4 次绘制（10-21 用户实测）；【推断】这 4 次可以用不同的 shader pass。
   - 【原文·代码】`iterations = 2` 时 `:78` 的循环跑两遍，纵向 RenderGraph pass 出现两次，都用 shader pass 0。
4. 【推断】一个 RenderGraph pass 里可以画 0 到多次，每一次画用一个 shader pass；SetPass 数的是 shader pass 之间切换的次数。
