## 速览：物理（10 分钟，不计入验收）

> 每日 Unity 速览第 4 篇（计划「每日 Unity 速览」，F40）。只认识概念，打开看一眼就停，不出自测题。

**前提**：Unity 6000.3 编辑器，任意场景。

1. **刚体（Rigidbody）**：【原文】[Unity 6.3 · Rigidbody component reference](https://docs.unity3d.com/6000.3/Documentation/Manual/class-Rigidbody.html)「A Rigidbody provides a physics-based way to control the movement and position of a GameObject.」（译：刚体提供一种基于物理的方式来控制游戏对象的运动和位置。）
2. **碰撞体（Collider）**：【原文】[Unity 6.3 · Introduction to collision](https://docs.unity3d.com/6000.3/Documentation/Manual/CollidersOverview.html)「A collider is a Unity component that defines the shape of a GameObject for the purposes of physical collisions.」（译：碰撞体是一个 Unity 组件，用来为物理碰撞定义游戏对象的形状。）同页说「Colliders are invisible」（译：碰撞体是看不见的。）
   <span style="color:red">刚体给的是受力后的运动（含往下掉）；碰撞体给的是碰撞用的形状，本身也是物理。只有碰撞体、没有刚体的静态碰撞体（static collider）仍能挡住带刚体的物体，所以不是全部物理性质都由刚体赋予（曾错写成「刚体赋予了物理性质」）</span>
3. **和渲染的关系**：【推断】物理算的是物体往哪动、撞没撞上；碰撞体看不见，不会被画出来，所以它本身不产生 draw call。

## 1. 打开 GPU Usage 模块（20 分钟）

2. 只能在 Play 模式测：【原文】GPU Usage 页「You can only use the GPU Profiler in Play mode, or for builds of your application.」（译：GPU Profiler 只能在 Play 模式下，或对打包出来的应用使用。）
3. DX12 可以用：【原文】同页「On Windows, Unity supports Play mode profiling in the Editor with Direct3D 11 and Direct3D 12 APIs only.」（译：在 Windows 上，编辑器里的 Play 模式性能分析只支持 Direct3D 11 和 Direct3D 12。）同页接着说「However, the overhead of running the Unity Editor affects the Profiler, which might make the profiling results less accurate.」（译：不过，运行 Unity 编辑器本身的开销会影响 Profiler，可能让分析结果不那么准。）

## 3. 找 4 个高斯 pass 各自的耗时（35 分钟）

**前提**【推断】：手册没写 GPU Usage 模块的明细里会不会按 RenderGraph pass 名列出。代码上看，编辑器里每个 RenderGraph pass 默认用 pass 名建一个性能采样（SRP Core 17.3 `RenderGraph.cs:2868-2880`），执行时包在这个采样里（`:2594`），所以大概率能搜到，但没有手册原文。先在 Profiler 下方的明细（Hierarchy）里搜下表的 pass 名（`GaussianBlur_RenderPass.cs:13-16`）；搜不到就写「未显示」，把你看到的最接近的条目名记下来交 Atlas，不猜。

**参数**：同第 2 节「开」那一行（1920×1080，高斯打开，`iterations = 1`、`downSample = 2`）。选一个平稳的帧。

| 步骤 | pass 名 | GPU ms（未显示就写「未显示」） |
|---|---|---|
| Downsample（第 76 行） | GaussianBlurDownsamplePass | 0.012 ms |
| Vertical（第 80-81 行） | VerticalGaussianBlurRenderPass | 0.025 ms |
| Horizontal（第 83-84 行） | HorizontalGaussianBlurRenderPass | 0.024 ms |
| Upsample（第 87 行） | GaussianBlurUpsamplePass | 0.037 ms |
| 合计 | — | 0.098 ms |

<span style="color:red">不能只凭写入分辨率断定 Upsample 最贵。Vertical / Horizontal 走 SampleGaussianBlur，每个像素采样 5 次（中心 1 次 + 偏移 4 次）；Upsample 那次调用没有用这个材质（曾错写成「消耗最多的就是 Upsample，没问题，因为它是 1920×1080」；「周围 4 个点」漏了正中间那 1 次）</span>
