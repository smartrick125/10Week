## 一、管线骨架（D1）

| 英文 | 中文 | 一句话 |
|---|---|---|
| SRP (Scriptable Render Pipeline) | 可编程渲染管线 | Unity 让你用 C# 自己写渲染流程的框架 |
| URP (Universal Render Pipeline) | 通用渲染管线 | Unity 基于 SRP 写好的一套管线 |
| RenderPipelineAsset | 管线资产 | 硬盘上的配置表，职责只有 `CreatePipeline()` |
| ScriptableRenderContext | 渲染上下文 | 命令的收件箱，`Submit()` 才真正发给 GPU |
| CommandBuffer | 命令缓冲 | 攒命令的容器；`ExecuteCommandBuffer` 是**拷贝**给 context，之后必须 `Clear()` |
| Culling | 剔除 | CPU 上算"哪些物体在视锥内"，结果是 `CullingResults` |
| ScriptableCullingParameters | 剔除参数 | **struct 不是 class**，`TryGet` 失败时是全零默认值 |
| DrawingSettings | 绘制设置 | 用哪个 shader pass（靠 `ShaderTagId` 匹配 `LightMode`） |
| FilteringSettings | 过滤设置 | 画哪一批（`RenderQueueRange`）—— **白名单，不是黑名单** |
| SortingSettings | 排序设置 | 什么顺序画（`SortingCriteria`）；URP 从不用默认值 |
| ShaderTagId / LightMode | 着色器标签 | 没写 `LightMode` 的 pass 归到 `SRPDefaultUnlit` |
| Render Target (RT) | 渲染目标 | 显存里的画布；URP 里包装成 `RTHandle` |
| Frame Buffer | 帧缓冲 | Color Buffer + Depth/Stencil Buffer |

## 二、Pass 调度（D2）

| 英文 | 中文 | 一句话 |
|---|---|---|
| ScriptableRendererFeature | 渲染器功能 | 挂在 Renderer Data 上的那个东西；`Create()` 只在序列化时刻调 |
| ScriptableRenderPass | 渲染通道 | 真正干活的 pass 对象；`EnqueuePass` 一次 = 队列里一格 |
| RenderPassEvent | 渲染通道事件 | **时刻，不是内容**。18 个取值，我的 Blur = `AfterRenderingSkybox` (400) |
| Injection Point | 注入点 | 源码里 `RecordCustomRenderGraphPasses(...)` 那些行 |
| Stable Sort | 稳定排序 | 事件值相等时保持挂载顺序；机制是 `<` 而非 `<=` |
| Draw Call | 绘制调用 | 提交几何让 GPU 画 |
| SetPass Call | SetPass 调用 | 一帧里切换 shader pass 的次数（Unity Statistics 窗口那一行叫 SetPass，界面显示 SetPass calls）；**和 Draw Call 是两回事**（W4-D1 第 2 节，10-21 改）|
| Depth Texture (`_CameraDepthTexture`) | 深度图 | URP Asset 里的勾，对应源码 `m_RequireDepthTexture` |
| Opaque Texture (`_CameraOpaqueTexture`) | 不透明图 | 同上，`m_RequireOpaqueTexture` |
| Frame Debugger | 帧调试器 | `Window → Analysis → Frame Debugger` |

## 三、RenderGraph（D3）

| 英文 | 中文 | 一句话 |
|---|---|---|
| Render Graph | 渲染图 | 节点是图形操作，边是资源依赖 |
| DAG (Directed Acyclic Graph) | 有向无环图 | **地基**：让 URP 知道 pass 之间谁依赖谁 |
| Pass Culling | 通道裁剪 | 输出没人读的 pass 整条剔掉；靠 DAG 反向追溯 |
| Resource Lifetime | 资源生命周期 | 图内临时资源从首次使用到末次使用（读、写都算）；按需创建／复用，末次使用后交还资源池。导入资源由外部管理 |
| Memory Aliasing | 内存别名 | 生命周期**不重叠**的 RT 复用同一块显存 —— 省**容量** |
| Pass Merging | 通道合并 | **attachment 一致**的相邻 **Raster** pass 合成一个 native pass —— 省**带宽**。Unsafe / Compute pass 不参与 |
| Native Render Pass | 原生渲染通道 | Frame Debugger 里 `(RP x:y)` 的 x；**x 相同 = 被合并** |
| Subpass | 子通道 | `(RP x:y)` 的 y |
| Attachment | 附件 | 一个 render pass 绑定的那组 RT |
| Tile Memory | 图块内存 | 移动 GPU 片上高速内存，不出芯片 |
| TBDR (Tile-Based Deferred Rendering) | 基于图块的延迟渲染 | **硬件架构**；这里的 Deferred ≠ Deferred Shading |
| Deferred Shading | 延迟着色 | **软件架构**：先写多张 G-Buffer 再统一算光照 |
| Load / Store | 加载 / 写回 | 不合并 = 每个 pass 结束 store 回显存、下个再 load 回来 |
| Bandwidth | 带宽 | 显存↔芯片之间搬数据的速率，移动端主要瓶颈 |
| Compatibility Mode | 兼容模式 | URP 的旧版渲染路径，17.3 已不是默认 |
| Render Graph Viewer | 渲染图查看器 | `Window → Analysis → Render Graph Viewer`（D4 主菜） |

## 四、GPU 流水线（手绘全景图用，W3 展开）

| 英文 | 中文 | 一句话 |
|---|---|---|
| Vertex Shader | 顶点着色器 | 输出裁剪空间坐标 |
| Primitive Assembly | 图元装配 | 顶点重组为三角形 |
| Clipping | 裁剪 | 在**齐次裁剪空间**做，判据 `-w ≤ x,y,z ≤ w` |
| Perspective Division | 透视除法 | ÷w → NDC |
| NDC (Normalized Device Coordinates) | 归一化设备坐标 | -1~1 |
| Screen Mapping | 屏幕映射 | NDC → 屏幕像素坐标（**W6 像素完美的主战场**） |
| Rasterization | 光栅化 | 判断哪些像素在三角形内 |
| Fragment Shader | 片元着色器 | 用插值数据算颜色 |
| Depth Test (ZTest) | 深度测试 | 不通过直接丢弃 |
| Depth Write (ZWrite) | 深度写入 | 和 ZTest 是两个独立开关 |
| Early-Z | 提前深度测试 | 深度测试提到片元着色之前，省掉被遮挡像素的着色 |
| Blending | 混合 | 与已有颜色混合 |
| Present | 呈现 | 最终把 RT 交给屏幕 |
| Shader Variants | 着色器变体 | 按 keyword 组合展开成多份分别编译；σ 这类材质属性不是 keyword，改它不产生新变体（推断，W3-D1 补） |

### W2-D1 · 高斯模糊

| 英文 | 中文 | 一句话 |
|---|---|---|
| Gaussian Blur | 高斯模糊 | 按高斯权重混合邻近纹素的颜色，得到当前输出颜色 |
| Gaussian Kernel | 高斯核 | 一组按采样偏移排列的权重；本例是中心、±1、±2 共 5 个 |
| Sigma (`σ`) | 标准差／核宽度参数 | 控制高斯权重随离中心距离增加而衰减的快慢；不是 `_BlurSpread` |
| `exp(x)` | 指数函数 | 表示 `e^x`；本例用 `exp(-i²/(2σ²))` 算未归一化权重 |
| Normalization | 归一化 | 每个未归一化权重除以总和 `S`，使 5 个权重之和为 1 |
| Convolution | 卷积 | 按位置取多个邻近颜色，分别乘对应权重，再求和得到一个输出颜色 |
| Separable Filter | 可分离滤波 | 二维高斯权重可写成 `G(x,y)=g(x)·g(y)`，因此可先纵向再横向；5×5 每像素采样由 25 次变为两遍各 5 次 |
| Downsampling | 降采样 | 把图像处理到较低分辨率；本例由 `downSample` 控制中间贴图尺寸 |
| Upsampling | 上采样 | 把低分辨率结果写到较高分辨率目标；尺寸放大不会恢复已丢失的细节 |
| Texel Size | 纹素尺寸 | 一个纹素在 UV 中的跨度；宽高为 `W×H` 时，`.xy=(1/W,1/H)` |
| Sampling Offset | 采样偏移 | 从当前 UV 移到邻近采样点的位移；本例由纹素尺寸、方向和 `_BlurSpread` 相乘得到 |
| Ping-Pong Buffers | 双缓冲交替读写 | 在 `tempA`、`tempB` 间轮流读写，避免同一遍模糊同时读写同一张纹理 |

### W2-D2 · Sobel 边缘检测与纹理输入

| 英文 | 中文 | 一句话 |
|---|---|---|
| Sobel Operator | Sobel 边缘检测算子 | 对 3×3 邻域的亮度分别求左右、上下变化，用变化量判断颜色边缘 |
| `Gx` / `Gy` | 水平／垂直方向卷积核 | `Gx` 检测左右亮度变化，`Gy` 检测上下亮度变化；它们是权重矩阵，不是最终响应值 |
| Luminance | 亮度 | 把采样的 RGB 按不同系数合成一个亮度值，再交给 Sobel 计算 |
| `edgeX` / `edgeY` | 两个方向的 Sobel 响应 | 3×3 亮度分别乘 `Gx`／`Gy` 并求和，得到左右／上下方向的变化量 |
| Edge Strength (`G`) | 边缘强度 | 本 shader 用 `abs(edgeX) + abs(edgeY)` 合成；与后面的反向遮罩不是同一个值 |
| `saturate(x)` | 限幅函数 | 把数值限制在 0～1；本例用 `saturate(1 - G)` 得到反向边缘遮罩 |
| Inverse Edge Mask | 反向边缘遮罩 | 本例边缘处接近 0、均匀处接近 1，用作最终颜色混合系数 |
| `_EdgeOnly` | 仅显示边缘的混合参数 | 0 为原图上显示边缘，1 为边缘色与背景色组成的画面；中间值在两种结果间混合 |
| `TextureHandle` | 渲染图纹理句柄 | 标识本次 Render Graph 录制＋执行中的逻辑纹理资源；不是 GPU 地址，也不保证已有实际纹理 |
| `BlitMaterialParameters` | Blit 参数包 | 保存这次 Blit 的源句柄、目标句柄、材质和 shader pass，本身不绘制 |
| `AddBlitPass` | 登记 Blit 通道的辅助方法 | 在图中登记节点、资源读写依赖和稍后执行的函数；调用时不立即绘制 |
| `_BlitTexture` | Blit 的 Shader 源纹理插槽 | 插槽名固定；每次 Blit 可绑定不同的源纹理资源，绑定不复制像素 |
| `_CameraTargetAttachment` | 相机颜色附件的资源名 | 本次 Frame Debugger 看到的相机颜色纹理名称，不是 `_BlitTexture` 插槽，也不是 GPU 地址 |

### W2-D3 · 漏检实测、σ 与 GPU 执行

| 英文 | 中文 | 一句话 |
|---|---|---|
| Unlit / Lit | 无光照／有光照材质 | Unlit 直接输出颜色，不受光照影响；Lit 的亮度随法线和光照方向变化 |
| Lambert Diffuse (`N·L`) | 兰伯特漫反射 | `漫反射 = 表面颜色 × 光颜色 × max(0, N·L)`；法线 N 不同 → 亮度不同 |
| Linear Color Space | 线性色彩空间 | shader 里算的是线性值；Inspector 显示的是 sRGB 值，手算前要先换算 |
| sRGB | 标准 RGB（伽马编码） | 线性 → sRGB：`s = 1.055 · L^(1/2.4) − 0.055`；暗部被提亮，所以 s > L |
| `B10G11R11_UFloat` | 无 alpha 的紧凑浮点格式 | 本工程相机颜色 RT 的格式；G 通道 11 位，0.3 附近步长约 0.004 |
| Quantization Error | 量化误差 | 颜色存储精度有限造成的舍入；1c 两侧亮度只能「近似相等」的原因 |
| Standard Deviation (`σ`) | 标准差 | 权重降到中心约 61% 的距离；±1σ／±2σ／±3σ 约占 68%／95%／99.7% 总权重 |
| Kernel Truncation | 核截断 | 采样范围不到 ±3σ 时两侧尾巴被截掉；5 点核做 σ = 2 就属于这种情况 |
| Ghosting | 重影 | `_BlurSpread` 拉大后中间纹素被跳过，一条细线变成几条分开的淡线 |
| Fullscreen Triangle | 全屏三角形 | 一个比屏幕大的三角形，只有 3 个顶点，全屏后处理都用它画 |
| Index Buffer | 索引缓冲 | 记录「哪 3 个顶点组成一个三角形」，让同一顶点只算一次、多个三角形共用 |
| Back-face Culling | 背面剔除 | 背对相机的三角形在光栅化前丢掉，不产生片元（`Cull Back`） |
| Interpolation | 插值 | 光栅化按 3 个顶点的值，给三角形内每个像素算出 uv 等数据 |
| Overdraw | 过度绘制 | 屏幕上重叠的区域被多次 draw 各算一遍片元 |
| Warp / Wavefront | 线程组（NVIDIA／AMD） | GPU 把 32（或 64）个顶点/像素打成一组，同一时刻执行同一条指令 |
| Barrier | 屏障／依赖等待 | 后一个 pass 要读前一个 pass 写的 RT 时，必须等它写完 |
| Uniform (Constant) | 常量参数 | C# 每帧设置一次，所有像素读到同一个值，如 `_BlurSpread` |
| RenderDoc | GPU 抓帧调试工具 | 能读单个像素值、看 Pixel History；Frame Debugger 做不到（W4 安装） |

### W3-D1 · 全屏 pass 算账

| 英文 | 中文 | 一句话 |
|---|---|---|
| Literal | 字面量 | 代码里直接写出的固定值（如 `19`）；HLSL 规定数组长度必须是字面量（错误 3058），所以 shader 数组长度不能运行时决定 |
| `Material.SetFloatArray` | 给材质传浮点数组 | C# 把算好的权重数组复制给 shader；数组长度第一次设定后不能再变，传更长的数组时多出的部分被忽略 |
| Sampling Cost Model | 采样数成本模型 | 一个全屏 pass 的采样数 = **写进的**目标 RT 像素数 × 每像素采样次数；本例 Upsample 写回全分辨率，所以降采样省不掉它 |
| RenderTarget field (Frame Debugger) | Frame Debugger 的 RenderTarget 字段 | 指上面「Render Target (RT)」那个渲染目标，也就是这个 pass **写**的目标；下方 Textures 里的 `_BlitTexture` 是**读**的源图（后半句是推断） |

### W3-D2 · 存储层级、寄存器与缓存

> 2026-10-16 收口：今日学习已结束。寄存器计算仍未掌握，相关条目只作补充材料，不计本次D2掌握或验收。第9d第4题未完成，明天先补齐比较数据与操作步骤，不由术语表推定已经掌握。

| 英文 | 中文 | 一句话 |
|---|---|---|
| VRAM | 显存 | GPU 用的大容量内存，在芯片外；纹理、RT、顶点缓冲、常量都放这里 |
| Cache Hit / Miss | 缓存命中／未命中 | 命中几十个周期，未命中要去显存取一整块、几百个周期 |
| Register | 寄存器 | 计算单元里最快的存储，每个像素一小份；数量在编译时定死 |
| Occupancy | 占用率 | 一个计算单元同时挂了多少组；受寄存器数和硬件最大组数两者限制 |
| SM (Streaming Multiprocessor) | 流式多处理器 | NVIDIA 对「一个计算单元」的叫法，内含寄存器堆和计算核心 |
| Latency Hiding | 延迟隐藏 | 某组等显存时立刻切去算另一组，用别人的计算填满等待时间 |
| Graphics API | 图形 API | DX12 / Vulkan / Metal 等统一接口，Unity 通过它跟各家驱动打交道 |
| GPU Driver | 显卡驱动 | 运行在 CPU 上，把 API 命令翻译成自家显卡的指令、管理显存 |
| DXBC / DXIL / SPIR-V / metallib | shader 中间格式 | Unity 先编成这些格式，驱动第一次用到时再翻译成机器指令；6000.3 的 DirectX 平台默认 FXC → DXBC，改用 DXC 才是 DXIL（V18，10-18 改） |
| Texture Cache Locality | 纹理缓存局部性 | 相邻像素采样位置挨着就能共用缓存；`_BlurSpread` 拉大会破坏它 |

### W3-D3 · 2026-10-18 tile 存储与 Load / Store

只收已落地笔记里的定义；依据见 W3-D2、W3-D3 笔记对应小节。

| 英文 | 中文 | 一句话 |
|---|---|---|
| bit / Byte (B) | 位 / 字节 | 1 B = 8 bit；bit 说格式精度（R8G8B8A8 每通道 8 bit），B 说数据量（每纹素 4 B） |
| MB / MiB | 兆字节 / 二进制兆字节 | 本笔记 1 MB = 1,000,000 B；1 MiB = 1,048,576 B 是另一种口径（NIST） |
| Gb/s vs GB/s | 位每秒 / 字节每秒 | 数值相同时差 8 倍；显存每引脚常写 Gb/s，系统带宽常写 GB/s、TB/s |
| External Memory Traffic | 外部内存流量（笔记里简称外存流量） | 在指定范围内累计的、GPU 所在芯片和芯片外部内存之间搬运的数据量，单位字节（如 MB）。外部内存在手机上是 DDR，独立显卡上是显存；基础课里「外存」常指硬盘，这里不是【推断·用词】。片上读写（Fragment Shader ⇄ tile memory）不算；例：一次完整 Store 一张 1920×1080×4 B 的目标，理论跨出芯片 8.2944 MB（V40） |
| IMR (Immediate Mode Rendering) | 立即渲染 | 按图元组织处理；缓存可保留最近访问的帧缓冲数据（Arm §2） |
| TBR (Tile-Based Rendering) | 分块渲染 | 先建立图元和屏幕块的关系，再处理块内片元；工作集可放片上 RAM（Arm §3） |
| RenderBufferLoadAction | 开始时的载入方式 | 开始向目标渲染时怎么处理旧内容：Load / Clear / DontCare 三选一，并列无父子关系 |
| RenderBufferStoreAction | 结束时的保存方式 | 目标渲染完时怎么处理新结果：Store / Resolve / StoreAndResolve / DontCare；和开始那次独立选 |
| DontCare（开始时） | 不关心旧内容 | 不保留旧内容，tile GPU 可省去加载；初值未定义，所以必须旧内容已经没用 |
