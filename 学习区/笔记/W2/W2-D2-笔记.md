## 2. 手算 3×3 Sobel（100 分钟）

先看 `EdgeDetection.shader` 中的 `Luminance()`、`Gx[9]`、`Gy[9]`、`offsets[9]` 与循环。`x/y` 在这里指邻域的两个方向；它们不是高斯模糊的权重。

**抄出两个 3×3 核（不要只写名字）**：

```text
Gx =                 Gy =
-1.0h 0.0h 1.0h       -1.0h -2.0h -1.0h
-2.0h 0.0h 2.0h       0.0h 0.0h 0.0h
-1.0h 0.0h 1.0h       1.0h 2.0h 1.0h
```

下面的数字已经是采样点的亮度，暂时不考虑 RGB 转亮度和纹理过滤。对中心像素，分别逐格算 `Σ(亮度 × Gx)` 和 `Σ(亮度 × Gy)`。

**A：亮度均匀的区域**

```text
0.5  0.5  0.5
0.5  0.5  0.5
0.5  0.5  0.5
```

`edgeX = 0`；`edgeY = 0`；`Sobel()` 最终返回 `1`。

**B：左暗右亮的边界**

```text
0  0  1
0  0  1
0  0  1
```

`edgeX` 逐行计算：1+2+1=4  
`edgeY` 逐行计算：-1+0+1=0  
`saturate(1 - abs(edgeX) - abs(edgeY)) = 0`

**解释**：为什么 `Gx` 对 B 有响应，而 `Gy` 对 B 的响应不同？为什么两个核的正负号整体反过来，最后的描边位置通常仍不变？
> 因为Gx是检测左右亮度差距的卷积核 而Gy是检测上下亮度的卷积核所以响应不同，shader会对每一个像素格算出一个遮罩值 算出0这个就是边缘像素 算出1就是普通像素 核的正负号反转同一个像素的edgeX和edgeY的响应会正负反转，但是最后会被取abs也就是绝对值所以生成的边缘像素不变

**`saturate` 做什么？`abs(edgeX) + abs(edgeY)` 与常见的 `sqrt(edgeX² + edgeY²)` 有什么区别？** __它做一个遮罩将结果限制在0~1。本diamagnetic用abs(edgeX)+abs(edgeY)算边缘强度，再用saturate(1-边缘强度)得到反向遮罩。绝对值相加与sqrt(edgeX^2+edgeY^2)的结果不总相同，例如0.3，0.4风别得到0.7，0.5；实际性能区别需要实测__

### `_BlitTexture` 小结

- `_BlitTexture` 是 `Blit.hlsl` 声明的 shader 源纹理绑定名；默认的 `AddBlitPass` 用这个名字传入本次要读取的纹理。它不是纹理像素的副本，也不是 C# `TextureHandle` 的地址。
- 第一次 Blit：源句柄 `srcCamColor` 对应的纹理绑定为 `_BlitTexture`，Sobel shader 采样后写入 `dst`。第二次 Blit：源句柄换成 `dst`，仍绑定为 `_BlitTexture`，Copy shader pass 写回 `srcCamColor`。
- `k_EdgeTextureName = "_BlurTexture"` 只是中间纹理的 Render Graph 资源名；它与 shader 输入名 `_BlitTexture` 是两回事。

### 补记：临时 RT 的生命周期（回看 W1-D3）

- 通用规则是**首次使用到末次使用**，读、写都算；“首次写到末次读”只描述先写后读的常见例子，不是所有 RT 的固定规则。
- 本例的 `dst`（资源名 `_BlurTexture`）由 `EdgeDetectionPass` 首次写入，随后由 `ED_CopyPass` 末次读取。图优化后若这两个 Pass 保留，Render Graph 在首次使用前创建或复用实际纹理，末次使用后将其交还资源池；交还不等于立即释放物理显存。
- 若相关 Pass 被裁剪，图内临时纹理可能根本不分配；通过 `ImportTexture` 导入的外部纹理不由 Render Graph 管理生命周期。
