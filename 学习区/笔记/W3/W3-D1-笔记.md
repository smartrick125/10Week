### 0b. shader 为什么要预留固定的最大采样数

> **本节前提（10-13 补，见问题反馈 F2）**：本节讨论的是**另一种设计**——想让 σ 可调时，C# 算好权重，用数组（array）传进 shader，再循环采样。你工程里的 `GaussianBlur.shader` 是 σ = 1 写死、手写 5 行采样的版本，**没有数组、也没有 σ 旋钮**，对照代码找不到题目说的东西是正常的。

#### 先读：σ 可调时，权重怎么从 C# 到 shader（10-13 补，见问题反馈 F5；已经 Verifier 查证 V6）

1. **链路**：C# 按 σ 算出一组权重 → `material.SetFloatArray` 把数值复制给 shader → shader 里声明的数组（如 `weights[19]`）接收 → 循环采样。C# 跑在 CPU、shader 跑在 GPU，各用各的内存，所以两边都要有一个数组。
   - 【原文】[Material.SetFloatArray](https://docs.unity3d.com/ScriptReference/Material.SetFloatArray.html)（Description 第 2 段）：“The array length can't be changed once it has been added to the block.” 传更长的数组时，“the extra items you tried to assign will be ignored.”
   - 【推断】「CPU、GPU 各用各的内存，所以两边都要有数组」。
2. **结构和数据分开**：数组有几格是程序结构，编译时定死；σ 和权重的值是数据，C# 每帧都可以换。
   - 【原文】数组长度必须是字面量（literal）：[HLSL errors and warnings](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/hlsl-errors-and-warnings) 错误 3058。
   - 【原文】编译时机：[Unity Manual · Shader compilation](https://docs.unity3d.com/Manual/shader-compilation.html)，构建时编译所需 shader；编辑器里按需编译，“it checks the Library/ShaderCache folder”。
   - 【推断】σ 是材质属性，不是关键字（keyword），不产生新的变体（variant），所以 σ 变了不会重新编译。依据：[Unity Manual · Shader variants](https://docs.unity3d.com/Manual/shader-variants.html)：“You configure variants using shader keywords.”
3. **值放哪边**：整个画面共用的值（σ、`_BlurSpread`）放 C#；每个像素、每个采样点都不同的值（偏移 i）在 shader 里算。【推断】由你工程的代码归纳。
4. **数组不是唯一做法**：也可以只传 σ，让 shader 按公式自己算权重，这样不需要数组。**本节讨论的是用数组的那种做法。**
   - 【原文】循环可以一直跑到遇到 break 为止，break 的条件可以看寄存器里的值：[loop (sm4 - asm)](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/loop--sm4---asm-)：“Specifies a loop which iterates until a break instruction is encountered.”（示例用 `if_nz r0.x` 判断 break）。所以循环次数可以由运行时的值决定。
   - 【原文】**条件**：次数随像素变化、循环里又用 `Sample` 时，会触发警告 3570：“A gradient instruction is used in a loop with varying iteration, which forces the loop to unroll.”（[HLSL errors and warnings](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/hlsl-errors-and-warnings)）。这时要改用显式 LOD 采样（如 `SampleLevel`）。
   - 【推断】代价是每个像素都要把权重重算一遍。

## 1. 成本模型（30 分钟）

W2-D3 复习区的结论：一次全屏 draw，片元着色器跑「目标 RT 的像素数」次。每次片元着色器里最贵的通常是**纹理采样**。

所以今天用一个简化模型：

```
一个全屏 pass 的采样数 = 目标 RT 像素数 × 每像素采样次数
一帧的总采样数 = 所有 pass 相加
```

1. 1920×1080 一共多少个像素？ __2,073,600__
2. 这个模型忽略了哪些成本？至少写 2 个（提示：W2-D3 复习区的「推论」和 1c 的 `B10G11R11`）。 __如果有模型重叠区域这个区域会被算两遍，之前只计算了会采样多少次，没算每次要从显存读多少字节这个字节数是由RT的格式决定的，限制就是带宽会对每秒有一个搬运上限__
