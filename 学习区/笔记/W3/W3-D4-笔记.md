## 4. 合并需要什么，实际怎么确认（35 分钟）

【原文】Unity 6.3 手册 [Get the current framebuffer from GPU memory in URP · Requirements / Use the SetInputAttachment API](https://docs.unity3d.com/6000.3/Documentation/Manual/urp/render-graph-framebuffer-fetch.html) 说明：输入附件（input attachment）由 `SetInputAttachment` 声明，着色器用 `LOAD_FRAMEBUFFER_X_INPUT` 读取。文档把该方式与片上帧缓冲读取和 pass 合并联系起来；支持 API 为 Vulkan、Metal，不支持的 API 会经显存拷贝。

【推断·范围】本节不把「同尺寸」「只读同位置」「打开 Native RenderPass」当作自动合并的充分条件，也不承诺所有采样都可改为输入附件。这只是排查入口；当前工程的实际合并结果以 Viewer 为准，移动端收益需要在相应设备验证。

【原文】[Render Graph Viewer window reference · Main window › Render passes / Pass List](https://docs.unity3d.com/6000.3/Documentation/Manual/urp/render-graph-viewer-reference.html) 列出：`Merge bar` 是已合并 pass 下方的蓝条；`Native Render Pass Info` 显示原生渲染通道信息；`Pass break reasoning` 说明当前 pass 为什么不能与下一 pass 合并。资源关联的蓝色提示与已合并蓝条要分清。

**操作参数**：相机 1920×1080，高斯模糊开启、边缘检测关闭，`iterations = 1`、`downSample = 2`；本表两行分别查看纵向模糊和向上采样。先记原设置：__`iterations = 1`、`downSample = 1`__。确认有效参数后打开 Render Graph Viewer，选 Game 相机（下拉里若有 Scene 视图相机，不要选它）、`Auto Update`。选择 pass 名，在 Pass List 中查看下列字段（2026-10-19 按 F39 改出处名，原写 Pass Inspector）。某项未显示就写「未显示」，不填猜测。

**观察前提**：观察对象是 Game 相机，Game 视图正在渲染；相机不直接向后台缓冲录制，材质及源、目标纹理有效，有效 `iterations = 1`，功能实际执行。先搜索表中两个通道名；某通道未出现时，该行记录“未出现，尚不能判断合并”，检查执行入口与相机、抓取配置。通道出现后才读合并字段；字段未显示就记录“未显示”，不推断原因。

| pass | 是否有与相邻 pass 共用的 Merge bar | Native Render Pass Info 原文 | Pass break reasoning 原文或未显示 |
|---|---|---|---|
| VerticalGaussianBlurRenderPass | NO | 未显示 | This is an Unsafe Render Pass. Only Raster Render Passes can be merged. |
| GaussianBlurUpsamplePass | NO | 未显示 | This is an Unsafe Render Pass. Only Raster Render Passes can be merged. |

**检查题前提**：只依据本表实际观察；编辑器当前图形 API 记录为 __<DX12>__，未在手机上测量。

从一条 `Pass break reasoning` 原文里指出阻止合并的条件；没有显示原因就记录缺的证据：__因为是个Unsafe Pass但是我不知道这么才算Unsafe 下面还写了Only Raster Render Pass can be merged就是说只有光栅化渲染通道可以合并 但是不去确定变为光栅化之后是不是合并的唯一条件可能还要使用附件一对一的采样形式 未实测__。
