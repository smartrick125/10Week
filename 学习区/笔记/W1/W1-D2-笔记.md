### 三个容易绕晕的点

**① Clear 在 Cull 之后，不是之前**

- `Cull` 是 **CPU 上算一份名单**（哪些物体在视锥内），算在内存里
- `Clear` 清的是 **GPU 上的画布**（RenderTarget 的颜色/深度缓冲）
- 两者操作的东西完全不同，**没有"先清才能算"的依赖**
- 而且 cull 失败要早退（:759），早退时连 clear 一张全屏 RT 的带宽都不该花

**② `RecordRenderGraph` 有两个同名方法，分属两个层级**

| | 谁的方法 | 干什么 |
|---|---|---|
| `ScriptableRenderer.RecordRenderGraph` | **渲染器级**（`ScriptableRenderer.cs:1243`） | 排序 + 触发所有 pass 的录制 |
| `ScriptableRenderPass.RecordRenderGraph` | **单 pass 级**（我的 `BlurRenderPass.cs:45`） | 声明**这一个 pass** 读哪张图、写哪张图 |

单 pass 级那个干的是**声明**，不是整合、也不是执行 —— **只登记"我要读谁、写谁"，一行都不画**。
为什么能只声明不执行 → **D3/D4 的正题**。

**③ `DrawRenderers` 不是调度的第四步，它在 pass 内部**

```
❌ 并列四步：Cull → SetupCameraProperties → 按 RenderPassEvent 调度 → DrawRenderers
✅ 正确层级：Cull → SetupCameraProperties → 按 RenderPassEvent 排序 → 逐个 pass 录制
                                                                       └─ 某个 pass 内部才调 DrawRenderers
```

> 手绘整机全景图上 a/b/c/d 那四行要改成这个层级。
> **全景图 ≠ W1 验收物**：验收要的是把 `c` 那一行展开成 pass 级时序 + 每个 pass 的输入输出 RT。

# 四、Frame Debugger 实证

**预测**：前 = Skybox，后 = Transparents
**实际**：

```
(RP 0:0) Draw Main Light Shadowmap
(RP 1:0) DrawOpaqueObjects   ┐ 同一个 RP 号 = 被合并
(RP 1:0) DrawSkybox          ┘
(RP 2:0) CopyDepth                 ← 1273
         VerticalBlurRenderPass    ← 1275，没有 RP 前缀
         HorizontalBlurRenderPass
(RP 3:0) CopyColor                 ← 1283
(RP 5:0) BlitFinalToBackBuffer
```

**❗对不上的地方（今天真正学到的）**：预测的紧邻是 Skybox / Transparents，实际却夹着 **CopyDepth / CopyColor**。
原因：源码里那两个 `if` 都成立了，而它们由 URP Asset 的两个勾决定 ——

```
Assets/Settings/PC_RPAsset.asset:22   m_RequireDepthTexture: 1
Assets/Settings/PC_RPAsset.asset:23   m_RequireOpaqueTexture: 1
```

**单变量实验已验证**：只取消这两个勾（不动渲染器、不动 feature），CopyDepth / CopyColor 一起消失，其余全不变。

> ⚠️ 不能用"换成 Mobile_RPAsset"来做这个实验：`Mobile_Renderer.asset:29` 是 `m_RendererFeatures: []`，
> 切过去 Blur 会整个消失，变量不干净。而且 Quality 每档有自己的 `customRenderPipeline` 覆盖，
> 改 Project Settings → Graphics 的默认值大概率不生效。

# 六、复习清单（盖住右边自测）

| 问题 | 答案 |
|---|---|
| `RenderPassEvent` 的名字代表内容还是时刻？ | **时刻**。我的 Blur 干的是后处理的活，却挂在"天空盒之后"这一刻。任何 pass 都能挂任何时刻 |
| 数值之间为什么留空档？怎么用？ | 留给自定义 pass 插队。底层是 int，可写 `AfterRenderingSkybox + 1` 精确插到某格之后、下一格之前 |
| `Create()` 多久调一次？ | 只在**序列化时刻**：`ScriptableRendererFeature.cs:77 OnEnable` / `:86 OnValidate` / Renderer 构造函数。**与帧无关** |
| `AddRenderPasses()` 多久调一次？ | **每帧 × 每个正在渲染的相机**，各一次（实测：Console 计数疯涨，且打出 `SceneCamera`） |
| 为什么 `new Material(shader)` 必须在 `Create()` 里？ | 放进 `AddRenderPasses()` 的话 60fps 双相机 = 每秒 new 出 120 个 Material，没人回收 |
| `SortStable` 为什么"稳定"？机制在哪？ | `2382` 行 `curr < list[j]` 是 **`<` 不是 `<=`**，事件值相等时不往前挪 → 保持 Renderer Data 上的挂载顺序 |
| `cameraType == CameraType.Game` 拦掉了谁？在哪一层拦？ | 拦掉 SceneView / Preview / Reflection。**Unity 照样每帧调我的 `AddRenderPasses`，是我自己在方法体内部把 `EnqueuePass` 拦下的** |
| CopyDepth / CopyColor 哪来的？ | URP Asset 的 Depth Texture / Opaque Texture 两个勾，用来生成 `_CameraDepthTexture` / `_CameraOpaqueTexture` |
| Frame Debugger 里 `(RP x:y)` 是什么？ | Native Render Pass 的编号：x = 第几个 native pass，y = subpass。**x 相同 = 被合并**（如 DrawOpaqueObjects 和 DrawSkybox 都是 RP 1:0） |
| 为什么我的 Blur 没有 RP 前缀？ | **没被合并**，原因是 **pass 类型**：`AddBlitPass` 产生的是 **Unsafe Render Pass**，Viewer 原话 `Only Raster Render Passes can be merged`。Unsafe pass 连 attachment 都没有。合并总开关：`PC_Renderer.asset:31 m_UseNativeRenderPass: 1`。**（D4 用 Render Graph Viewer 更正：早先记的「attachment 变了」不是 Unity 给的原因）** |

# 七、方法论（这几条比知识点更值钱，W4 全程要用）

1. **往下读实现 vs 往上读调用方**：问"这个方法干了什么"往下读；问"多久调一次 / 什么时候调"**只能往上找调用方**。D2 卡住过一次就是方向搞错了。
2. **搜关键词要看行首**：`RecordCustomRenderGraphPasses(...)` 是调用，`RenderPassEvent.X <= y` 是比较。栽过三次。
3. **单变量实验**：换 RP Asset 会同时换掉渲染器和 feature 列表 → 结论作废。只动那一个勾才叫对照。
4. **先预测再抓帧**：对得上的地方没有信息量，**对不上的地方才是今天学到的东西**。
5. **磁盘 ≠ 编辑器内存**：Inspector 改完不 `Ctrl+S`（File → Save Project），`.asset` 文件不会更新。
