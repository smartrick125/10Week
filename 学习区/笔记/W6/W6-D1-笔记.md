**拓展：去掉 downsample 后，第一轮模糊范围为什么会变**（Atlas 答疑 11-05，不属于验收内容）
- 偏移公式写在 shader 里：两步版 `GaussianBlur.shader:31` `offset = _BlitTexture_TexelSize.xy * direction * _BlurSpread`；一步版 `:87` `_BlitTexture_TexelSize.xy * Point * _BlurSpread`，写法相同。现在工程跑的是一步版（C# 里两步版 `:83-87` 已注释）。
- `_BlitTexture` 是这一次 pass **读的那张图**（`AddBlitPass` 的源），不是写的目标。
- 【原文】[Unity 6.3 · Texture properties › Texture size](https://docs.unity.com/en-us/engine/6000.3/manual/materials-and-shaders/shaders/writing-custom/shader-writing/writing-shader-change-properties/material-properties-texture-properties)「{TextureName}_TexelSize - a float4 property contains texture size information: x contains 1.0/width」（译：{纹理名}_TexelSize——一个 float4 属性，包含纹理尺寸信息：x 是 1.0/宽度）。
- 【推断】公式不变，`_BlitTexture_TexelSize` 跟着读哪张图变。以 1920 宽、`downSample = 2`、`_BlurSpread = 1` 为例：
  - 有 downsample：第一轮读 `tempA`（960 宽），每步 1/960 UV，屏幕上走 2 个像素。
  - 没有 downsample：第一轮读 src（1920 宽），每步 1/1920 UV，屏幕上走 1 个像素。
  - 所以第一轮采样步长减半（最远 ±4 → ±2 屏幕像素），覆盖的源像素从 10 个变成 6 个【推断，按 D3D 线性采样规则算】。
- 【推断，按 D3D11.3 线性采样规则算】两种写法都是从全尺寸的 src 读、写进小 RT。`downSample = 2` 时，双线性正好平均 2×2，都不走样。
- 【推断，按 D3D11.3 线性采样规则逐值算】`downSample` 取 3 或更大时跳不跳纹素。前提：1920 宽、`_BlurSpread = 1`。取 3–6 时，跳不跳是两种写法的区别；取 7、8 时两种都跳，现写法跳得少（每行读到的源纹素：7 时 1644 对 548；8 时 1440 对 480）。
  - 旧写法（先 downsample）：downsample 那一次 Blit，每 `downSample` 个源纹素只读到 1–2 个，其余跳过，后面再也读不回来。`downSample = 3` 时采样点正好落在纹素中心，只读 1 个。
  - 现写法（去掉 downsample，一步版）：第一轮直接对 src 采 5×5 个点（每个方向 5 个），`downSample` ≤ 6 都能读到全部源纹素（只是权重不均），7 起才跳。
  - 两步版第一轮的竖向 pass，横向每 `downSample` 列只读 1–2 列，和旧写法一样会跳。
  - `_BlurSpread` 调小会更早跳（0.5 时从 5 起，0.2 时从 4 起）；调大到 3 也会跳（`downSample = 3` 时只读到 642/1920）。
- 所以去掉 downsample 只在 `downSample = 1` 时和原来**采样位置**等价。
- 【推断】数值上仍可能略有不同：tempA 是 `RenderTextureFormat.Default`（通常是 8 位的 ARGB32），本工程开了 HDR。旧写法先把 src 拷进 tempA，超过 1 的亮度被截掉再模糊；现写法先模糊 HDR 原值。场景里有亮度超过 1 的像素时，两者结果不同。

## 1. 整数缩放：为什么非整数倍会让像素宽窄不一（20 分钟，读）

1. **像素风的做法**：先把画面画到一张小图上（比如 480×270），再放大到屏幕。小图上的 1 个像素，就是 1 个美术像素。
2. **放大时屏幕像素去哪里取色**：最近邻（nearest-neighbor）放大时，每个屏幕像素取离它中心最近的那个源像素。
   - 【原文】[Microsoft · Coordinate Systems (Direct3D 10)](https://learn.microsoft.com/en-us/windows/win32/direct3d10/d3d10-graphics-programming-guide-resources-coordinates)「Pixel centers are offset by (0.5f,0.5f) from integer locations.」（译：像素中心相对整数位置偏移 (0.5, 0.5)。）
   - 【原文】同页「Point sampling: Texel # = floor(U * Width)」（译：点采样：纹素编号 = floor(U × 宽度)。）
   - 【推断】URP 放大那一步的 UV 从屏幕左边 0 铺到右边 1，所以屏幕第 x 个像素（从 0 数）的 U = (x + 0.5) ÷ 屏宽，取源图第 ⌊(x + 0.5) × 源宽 ÷ 屏宽⌋ 格。
   - 【原文】[FilterMode.Point](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/filtermode/point)「Point filtering - texture pixels become blocky up close.」（译：点过滤——纹理像素在近处变成一块一块的。）点采样（point sampling）就是这种取法。
3. **整数倍的例子**：源图 3 格放大到屏幕 6 格（2 倍）。u = (x + 0.5) × 0.5，x = 0…5 依次是 0.25、0.75、1.25、1.75、2.25、2.75，取整得 0、0、1、1、2、2。每个源像素各占 2 格，一样宽。
4. **换成双线性会怎样**：【原文】[FilterMode.Bilinear](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/filtermode/bilinear)「Bilinear filtering - texture samples are averaged.」（译：双线性过滤——纹理样本被平均。）【推断】相邻两个美术像素的颜色被混在一起，像素边缘变糊，这正是像素风不要的。
5. **URP 自己也按这条规则选过滤**：【原文】[Unity 6.3 · URP Asset reference](https://docs.unity.com/en-us/engine/6000.3/manual/render-pipelines/universal-render-pipeline/urp-reference/universalrp-asset) Upscaling Filter 的 Automatic「If integer scaling is possible, Unity selects the Nearest-Neighbor option, otherwise Unity selects the Bilinear option.」（译：如果可以整数缩放，Unity 选最近邻；否则选双线性。）
   - 【原文·代码】URP 17.3 `UniversalRenderPipeline.cs:2261-2282`：Automatic 时先算 1 ÷ Render Scale，是整数，并且屏宽、屏高除以它也都是整数，才用 `ImageUpscalingFilter.Point`；否则用默认的 `Linear`。
   - 【原文·代码】但选出 Point 不等于放大时真用最近邻。后处理关时，最后一步 `BlitFinalToBackBuffer` 按源图的过滤方式选 pass（`FinalBlitPass.cs:252`），相机的中间颜色图一律建成双线性（`UniversalRendererRenderGraph.cs:1829`），所以用的是 `BilinearDebugDraw`。
   - 【原文·代码】点采样只在 Pass 为 `FinalPost` 的那一步打开（`PostProcessPassRenderGraph.cs:2410-2414`，打开 `_POINT_SAMPLING`）。
   - 【原文·代码】`FinalPost` 要后处理开着，并且满足以下之一才跑：放大过滤不是 Linear、开了 FXAA、开了 TAA 锐化（`UniversalRendererRenderGraph.cs:1381-1384`）。本场景 `Camera1` 抗锯齿是 None（`Chapter12.2.unity:741`），只看第一条。
   - 所以本场景要看到最近邻放大，`Camera1` 的后处理得开着（第 3 节实测）。

## 今天学到了什么（收口）

1. **只有整数倍加最近邻，每个美术像素才一样宽**：3 格放大到 6 格，各占 2 格；放大到 8 格，各占 3、2、3 格（第 1 节、第 4 节题 1）。
2. **设置里选出的过滤，不等于放大那一步真用的过滤**：Automatic 在 0.25 时选出 Point，但后处理关时，最后一步 Pass 是 `BilinearDebugDraw`，还是双线性（第 1 节第 5 条、3a 表）。
3. **看实际用哪种放大，在 Frame Debugger 里看最后一步的 Pass 名**：`BilinearDebugDraw` 双线性、`NearestDebugDraw` 最近邻、`FinalPost` 再看有没有 `_POINT_SAMPLING`、`UberPost` 只有双线性（第 3 节判断方法）。
4. **眼睛看到的和 Pass 读数对得上**：0.25 开后处理是硬台阶；0.25 关后处理、0.3 开后处理都发糊（3b 表）。
5. **手册也可能和实测对不上**：手册说开后处理时最近邻不起作用，本工程代码和实测正相反，以代码和实测为准，原因未验证（留给以后第 1 条）。
6. **W5 验收**：同一个优化，整帧变不变快，看它改的是不是瓶颈；判等上屏受限看等待时间是否大于 0.5 ms，不拿它和 CPU、GPU 比大小（第 0 节验收题）。
